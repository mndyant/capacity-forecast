# 業務向けUIとサマリ出力

## 変更内容

- 画面名を「容量予測・整備計画」に統一し、説明的な見出し「予測条件」「予測結果」「使用量の実績・予測」「増加率別の比較」を採用。
- PCでは左に入力、右に結果を配置。スマホでは縦並び。警戒水準・比較増加率は詳細設定に集約。
- サマリに現状・予測・着手期限・対応事項・過去バックテストの評価を表示。
- サマリのTXT保存、結果JSONへの同じサマリの追加。UTF-8 BOM付きTXTは日本語を保ったまま保存できる。
- CSVの選択状態を表示し、解除ボタンを追加。条件変更後・エラー時は再計算するまで出力ボタンを無効化。

サマリ生成は `app/summary.py` が計算済み結果を整形するだけで、予測の再推定や外部通信は行わない。既存の観測CSVで足りるため、追加の入力データは作成していない。元の実績、予測手法、選択規則、整備日数からの期限計算は変更していない。

## 検証

- `.venv/Scripts/python -m pytest -q -p no:faulthandler`：50件成功。既存44件に加え、満杯・期限超過・着手計画・警戒到達・未到達のサマリと、評価済みサンプルの予測値・パラメータ・期限・選択モデルの一致を確認。
- `.venv/Scripts/python -m tests.ui_check --browser-path <既存Chromium>`：1280pxと390pxで入力から出力まで確認。ページの横はみ出しなし。
- TXTを実際にダウンロードし、JSONのサマリ文字列との完全一致を確認。入力変更後・CSVエラー時の出力停止、CSV解除、二重送信防止も確認。
- 意図した不正CSVの400以外にブラウザエラーなし。外部リクエスト0件。PCとスマホのスクリーンショットを目視確認。

## 評価記録の扱い

評価済みの元版はコミット `b09f064`・タグ `evaluation-v1` に保存。変更前に全ハッシュ照合が一致することを確認した。元の最終120ケースの採点は再実行しておらず、結果や凍結記録も書き換えていない。

現行版はUI・APIのソースが異なるため、元の全ソースハッシュとの照合は不一致となる。タグからの再現方法はREADMEを参照。今回の変更で最終評価の精度が改善したという主張はしない。既存評価の90日予測が単純な比較基準を下回ること、合成データで評価／実データ未検証という制約は維持する。
