# 評価設計と結果

**合成データで評価／実データ未検証。** 本結果は架空データに対する検証であり、銀行や他の実務での精度ではありません。

最終評価の選択手法は7/30日の平均MAEで比較基準をわずかに下回りましたが、90日では悪化しました。短期の開発スコアによるモデル選択が、長期の予測を良くするとは限らない結果です。結果を見た後に手法・閾値・容量・seedを変更していません。

監査を進める際はその起点までに観測済みになった行を再学習へ使います。モデルの種類は開発区間の結果で固定し、監査や未来の正解で再選択しません。各foldの重複するテスト窓を独立標本として扱った信頼区間はありません。

## 最終採点前に固定したもの

[protocol.json](../evaluation/protocol.json)に設定、[frozen.json](../evaluation/results/final-v1/frozen.json)に設定・ソース・データのSHA-256と依存バージョンを保存しました。凍結は2026-10-02 15:10:35 UTC（日本時間2026-10-03 00:10:35）。採点後の `verify` で一致を確認しました。

- 比較基準は直近30増分平均。線形は全履歴の傾き、最終観測にアンカー。指数平滑化は増分にα=0.2、初期値は最初の増分。
- 候補数は3。開発foldの**30日間全体のMAE平均**を最小化し、最良値×1.05＋0.01GB以内なら mean30 → linear → ses の順で優先。
- 各モデルへ同じdate/used_gbの観測履歴を渡し、同じ起点・同じ正解で比較。異なる履歴窓の利用は固定されたモデル仕様です。
- 容量はseed偶数1100GB、奇数2200GB。正解に合わせた変更はしません。リードタイム30日、安全余裕7日。
- seedとシナリオIDを使って生成器の乱数ストリームを分離。seed・シナリオ名・未来イベントはモデルに渡しません。
- 最終採点器は予測を作成した後にだけtruthファイルを読みます。日々の正解による90日予測の途中更新はしません。

Claudeのレビューによる境界検証・凍結対象・失敗記録の修正は最終凍結前に実施しました。探索結果は [development-v1](../evaluation/results/development-v1/report.md) に残しています。探索後の修正は評価記録とAPI/UIの信頼性を改善するもので、予測式・選択規則・容量・seedを探索スコアに合わせて変更していません。

## 未使用90日での全体結果

「7日」は1〜7日、「30日」は1〜30日、「90日」は1〜90日全体を採点したMAEです。終点だけの誤差とは区別しています。各行120ケース、失敗0件。各ケースの期間MAEを等しい重みで平均します。

|手法|7日MAE GB|30日MAE GB|90日MAE GB|90日中央値|90日最悪MAE|90日RMSE|90日終点絶対誤差|
|---|---:|---:|---:|---:|---:|---:|---:|
|直近30日平均（基準）|4.666|13.851|34.039|17.334|289.587|69.136|70.220|
|線形トレンド|5.979|19.307|63.414|48.507|170.625|99.004|137.313|
|増分の指数平滑化|2.887|8.452|32.683|15.946|188.506|59.409|75.287|
|開発区間で選択した手法|4.340|13.200|45.570|46.883|188.506|76.799|103.586|

選択手法の「全ケース平均MAEの比」による改善率は7日 **+6.98%**、30日 **+4.70%**、90日 **−33.88%**。基準誤差が0ならN/Aです。ケースごとの改善率とその平均もJSONに残していますが、小さい基準誤差で比率が極端になるため、全体平均の比とは区別します。

MAEは平均的なずれ、RMSEは大きなずれを重く扱う指標。RMSEはケースごとのMSEを平均してから平方根を取ります。累積増加量は予測・正解とも同じ最終実績を差し引くので、累積増加量の終点誤差は使用量の終点誤差と一致します。独立した精度の証拠を二つ得たことにはなりません。増加量が小さいケースがあるため、MAPEは主指標にしていません。

## 容量不足日と着手期限

90日内に予測・正解の両方で到達する場合だけ、日付の差を計算します。正の差は予測の遅れです。同じ整備期間＋安全余裕を引くため、着手期限の誤差は到達日誤差と同値です。

|手法|比較可能|到達日／着手期限MAE 日|見逃し|誤警報|両方未到達|既に満杯|
|---|---:|---:|---:|---:|---:|---:|
|比較基準|34|0.971|0|0|70|16|
|線形|34|0.765|0|0|70|16|
|指数平滑化|34|1.706|0|0|70|16|
|選択手法|34|0.676|0|0|70|16|

未到達70件と既に満杯16件は日付誤差から除外し、0日として混ぜていません。既に満杯のケースは、未来の不足日を予測する比較対象にはしません。正解だけ到達すれば見逃し、予測だけなら誤警報です。7/30日の分類・符号付き日付誤差・各ケースの期限は全件CSVにあります。

**この容量設定では90日の見逃し・誤警報が0件でしたが、検知性能が高い証拠とは考えません。** 容量を1100/2200GBの2値で固定したため、境界近くの難しいケースが少なく、16件は既に満杯でした。最終結果を見て容量を変更すると評価条件の後付けになるため、そのまま公開しています。分類分岐は手計算テストで確認していますが、実務の見逃し率は未検証です。期間直後に到達するケースも期間内未到達扱いになる、打ち切りの制約があります。

## 残る限界

生成器には6種類の仮定しかなく、実務での削除・欠損・圧縮・増設・業務イベント・制度変更・観測遅延を再現していません。初期使用量や日次ペースの幅も狭く、非減少条件に限定しています。年周期の推定、確率付き予測区間、為替、LLM接続は実装していません。実データと業務判断の損失を踏まえた検証が次の課題です。
